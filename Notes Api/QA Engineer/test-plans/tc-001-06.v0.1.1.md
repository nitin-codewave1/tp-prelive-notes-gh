# TC-001-06: [error] the list endpoint queries notes

**Story:** [[US-001-02]]
**Module:** retrieve the note list with pinned notes shown first

## Preconditions
pinned data is missing or null for a legacy note record

## Expected Result
the note is treated as pinned=false and included in the unpinned group without error

## Acceptance Criteria
Given a mix of pinned and unpinned notes exist, when GET /notes is called with no filters, then all pinned notes appear before unpinned notes, each group ordered newest-first
Given no notes are pinned, when the list endpoint is called, then notes are returned newest-first exactly as before the pinned feature existed
Given pinned data is missing or null for a legacy note record, when the list endpoint queries notes, then the note is treated as pinned=false and included in the unpinned group without error

## Planned Playwright Steps

| # | Instruction | Action | Selector | Value |
|---|---|---|---|---|
| 1 | Seed a legacy note record with pinned missing or null directly in the data store | navigate | `/notes` | POST seed legacy note pinned=null |
| 2 | Send a GET request to /notes | navigate | `/notes` | GET |
| 3 | Assert the legacy note appears in the unpinned group without errors | assert_text | `response.body` | legacy note treated as pinned=false |
