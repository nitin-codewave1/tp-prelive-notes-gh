# TC-001-07: the search/filter endpoint returns results

**Story:** [[US-001-03]]
**Module:** search or filter notes while pinned-first ordering is preserved

## Preconditions
a search query or tag filter matches both pinned and unpinned notes

## Expected Result
matching pinned notes are listed before matching unpinned notes, newest-first within each group

## Acceptance Criteria
Given a search query or tag filter matches both pinned and unpinned notes, when the search/filter endpoint returns results, then matching pinned notes are listed before matching unpinned notes, newest-first within each group
Given a search query matches only unpinned notes, when results are returned, then results are ordered newest-first with no pinned group present
Given a search query matches zero notes, when the endpoint is called, then an empty result array is returned with no ordering error

## Planned Playwright Steps

| # | Instruction | Action | Selector | Value |
|---|---|---|---|---|
| 1 | Seed notes so that a search query or tag filter matches both pinned and unpinned notes | navigate | `/notes` | POST seed matching pinned and unpinned notes |
| 2 | Send a GET request to /notes with a search query or tag filter | navigate | `/notes?q=term` | GET |
| 3 | Assert matching pinned notes are listed before matching unpinned notes, newest-first within each group | assert_text | `response.body` | pinned matches first, newest-first within groups |
