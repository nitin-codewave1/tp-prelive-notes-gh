# TC-001-02: [error] the API validates the request body

**Story:** [[US-001-01]]
**Module:** set the pinned flag when creating or editing a note via the API

## Preconditions
the pinned field is sent as a non-boolean value

## Expected Result
a 400 validation error is returned and the note is not saved

## Acceptance Criteria
Given a valid create or update request includes pinned: true, when the API processes the request, then the note is stored with pinned=true and the response reflects pinned=true
Given the pinned field is sent as a non-boolean value, when the API validates the request body, then a 400 validation error is returned and the note is not saved
Given the pinned field is omitted from a create request, when the note is created, then pinned defaults to false

## Planned Playwright Steps

| # | Instruction | Action | Selector | Value |
|---|---|---|---|---|
| 1 | Send a POST request to /notes with pinned set to a non-boolean value | navigate | `/notes` | POST {"title":"Note","body":"content","pinned":"yes"} |
| 2 | Assert the response status is 400 | assert_text | `response.status` | 400 |
| 3 | Assert the note was not saved by listing notes and confirming no matching record exists | assert_text | `response.body` | note not found |
