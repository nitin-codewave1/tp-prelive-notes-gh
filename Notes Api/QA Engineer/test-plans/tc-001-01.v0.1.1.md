# TC-001-01: the API processes the request

**Story:** [[US-001-01]]
**Module:** set the pinned flag when creating or editing a note via the API

## Preconditions
a valid create or update request includes pinned: true

## Expected Result
the note is stored with pinned=true and the response reflects pinned=true

## Acceptance Criteria
Given a valid create or update request includes pinned: true, when the API processes the request, then the note is stored with pinned=true and the response reflects pinned=true
Given the pinned field is sent as a non-boolean value, when the API validates the request body, then a 400 validation error is returned and the note is not saved
Given the pinned field is omitted from a create request, when the note is created, then pinned defaults to false

## Planned Playwright Steps

| # | Instruction | Action | Selector | Value |
|---|---|---|---|---|
| 1 | Send a POST request to /notes with a valid body including pinned:true | navigate | `/notes` | POST {"title":"Pinned Note","body":"content","pinned":true} |
| 2 | Assert the response status is 201 and the created note has pinned:true | assert_text | `response.body.pinned` | true |
| 3 | Fetch the note via GET /notes/{id} and assert pinned is persisted as true | assert_text | `response.body.pinned` | true |
